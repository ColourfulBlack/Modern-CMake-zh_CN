C++ 标准

CMake 对选择 C++ 标准有着非常出色的支持，最高已覆盖到 C++26。推荐的做法有两种：按目标设置的编译特性（compile features），以及相关的标准变量与属性。这两种方式在本书要求的最低 CMake 版本之前就早已存在，按需选用即可。

元编译器特性¶

功能最强大、语法最优雅，且在为目标（target）混用不同标准与选项时表现最好的方式，是使用 target_compile_features 配合 cxx_std_* 元特性。假设你有一个名为 myTarget 的目标，写法如下：

target_compile_features(myTarget PUBLIC cxx_std_11)
set_target_properties(myTarget PROPERTIES CXX_EXTENSIONS OFF)

对于第一行，你可以从 cxx_std_11、cxx_std_14、cxx_std_17（均为 CMake 3.8+）、cxx_std_20（CMake 3.12+）、cxx_std_23（CMake 3.20+）以及 cxx_std_26（CMake 3.25+）中进行选择。第二行是可选的，但添加它可以避免启用编译器扩展；如果不加这一行，CMake 可能会使用类似 -std=gnu++11 的标志来替代 -std=c++11。第一行甚至对 INTERFACE 目标也同样有效；而只有实际参与编译的目标才能使用第二行。

如果依赖链下游的目标指定了更高的 C++ 标准级别，这种方式也能很好地协同工作；所指定的标准会被视为最低要求，最终会采用所有请求中最高的标准。

Note

CMake 3.1 最初支持细粒度的编译特性（如 cxx_constexpr），允许你按需请求单个语言特性而非整个标准（参见完整列表）。但这种做法难以扩展；CMake 在 C++14 之后就停止了添加细粒度特性，如今官方文档也引导你改用 cxx_std_* 元特性。

全局设置与属性设置¶

支持 C++ 标准的另一种方式是设置一组特定的三个属性（全局级别和目标级别均可）。全局级别的设置如下：

set(CMAKE_CXX_STANDARD 11 CACHE STRING "The C++ standard to use")
set(CMAKE_CXX_STANDARD_REQUIRED ON)
set(CMAKE_CXX_EXTENSIONS OFF)

第一行设置了 C++ 标准的级别，第二行告诉 CMake 必须启用该标准，最后一行是可选的，用于确保使用 -std=c++11 而非类似 -std=gnu++11 的标志。这种方法对于最终软件包（final package）来说还不错，但不应该在库（library）中使用。你应该始终将它设置为缓存变量，这样就可以很方便地覆盖它以尝试新的标准版本（或者万一它被当作库使用时，这也是唯一能覆盖它的方式——但还是要重申，不要在库中使用这种方式）。你也可以在目标上设置这些属性：

set_target_properties(myTarget PROPERTIES
    CXX_STANDARD 11
    CXX_STANDARD_REQUIRED YES
    CXX_EXTENSIONS NO
)

这种方式比全局设置更好，但仍然不像编译特性那样能够显式控制如何填充 PRIVATE 和 INTERFACE 属性，因此它实际上也只适用于最终目标（final targets）。

你可以在 Craig Scott’s useful blog post 中找到关于这些方法的更多信息。

Danger

不要自己手动设置编译标志。如果这么做，你就必须自己负责为每个编译器的每个发行版维护正确的标志，遇到不支持的编译器时也得不到有用的报错信息，而且某些 IDE 可能无法识别手动设置的标志。
