在 CMake 中运行其他程序

在配置时运行一条命令¶

在配置时运行一条命令相对比较容易。可以使用 execute_process 来运行进程并获取其结果。一般来说，避免在 CMake 中硬编码程序路径是一个好习惯；你可以使用 ${CMAKE_COMMAND}、find_package(Git) 或 find_program 来获取所要运行的命令。使用 RESULT_VARIABLE 来检查返回码，并使用 OUTPUT_VARIABLE 来获取输出。

下面是一个更新所有 Git 子模块的例子：

find_package(Git QUIET)

if(GIT_FOUND AND EXISTS "${PROJECT_SOURCE_DIR}/.git")
    execute_process(COMMAND ${GIT_EXECUTABLE} submodule update --init --recursive
                    WORKING_DIRECTORY ${CMAKE_CURRENT_SOURCE_DIR}
                    RESULT_VARIABLE GIT_SUBMOD_RESULT)
    if(NOT GIT_SUBMOD_RESULT EQUAL "0")
        message(FATAL_ERROR "git submodule update --init --recursive failed with ${GIT_SUBMOD_RESULT}, please checkout submodules")
    endif()
endif()

在构建时运行一条命令¶

在构建时运行命令要稍微棘手一些。主要的复杂性来自目标系统（target system）：你希望命令在什么时候运行？它是否会产生另一个目标所需要的输出？带着这些问题，我们来看一个调用 Python 脚本生成头文件的例子：

find_package(Python REQUIRED COMPONENTS Interpreter)
add_custom_command(OUTPUT "${CMAKE_CURRENT_BINARY_DIR}/include/Generated.hpp"
    COMMAND "${Python_EXECUTABLE}" "${CMAKE_CURRENT_SOURCE_DIR}/scripts/GenerateHeader.py" --argument
    DEPENDS some_target)

add_custom_target(generate_header ALL
    DEPENDS "${CMAKE_CURRENT_BINARY_DIR}/include/Generated.hpp")

install(FILES ${CMAKE_CURRENT_BINARY_DIR}/include/Generated.hpp DESTINATION include)

在这里，头文件的生成会在 some_target 完成后进行，并且当你不指定目标直接运行 make 时也会自动执行（ALL）。如果你使用 add_dependencies 将它设为另一个目标的依赖项，就可以省略 ALL 关键字。或者，你也可以要求用户在构建时显式地构建 generate_header 目标。

内置的常用工具¶

编写跨平台 CMake 构建脚本的一个实用工具是 cmake -E <mode>（在 CMake 文件中通常写作 ${CMAKE_COMMAND} -E）。这种模式允许 CMake 在不显式调用系统工具的情况下完成各种操作，例如 copy（复制）、make_directory（创建目录）和 remove（删除）。它主要用于构建阶段的命令。需要注意的是，非常实用的 create_symlink 模式过去仅支持 Unix 系统，但在 CMake 3.13 中也添加了对 Windows 的支持。点击这里查看对应文档。
