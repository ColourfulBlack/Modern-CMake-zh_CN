基础知识简介

最低版本要求¶

这是每个 CMakeLists.txt（即 CMake 所查找的固定文件名）的第一行：

cmake_minimum_required(VERSION 3.15)

顺便提一下关于 CMake 的语法。命令名 cmake_minimum_required 是不区分大小写的，所以常见的做法是使用小写[1]。VERSION 是这个函数的特殊关键字，紧跟在关键字后面的是版本号的值。和本书其他地方一样，只需点击命令名称即可查看其官方文档，并且可以使用下拉菜单在不同 CMake 版本的文档之间切换。

这一行很特殊[2]！CMake 的版本还会决定其策略（policies），这些策略定义了行为上的变化。CMake 不再保留最古老的旧行为：从 CMake 4.0 开始，将 cmake_minimum_required（或版本范围的起始值）设置为低于 3.5 会直接报错，而低于大约 3.10 的值则会产生弃用警告。因此请选择一个现代的最低版本，例如下方推荐的版本范围。你可以在 policies 中查看策略与版本的完整列表。

从 CMake 3.12 开始，版本号支持指定一个范围，例如 VERSION 3.15...4.4；这意味着你最低支持到 3.15 版本，同时也使用最高至 4.4 版本的新策略设置进行过测试。这对需要更优设置的用户友好得多，并且由于语法上的一个巧妙设计，它可以向后兼容旧版本的 CMake（尽管实际运行 CMake 3.1-3.11 时只会设置旧版本的策略，因为那些版本不会对该语法做特殊处理）。新版本的策略往往对 macOS 和 Windows 用户最为重要，而他们通常也会使用非常新的 CMake 版本。

当你开始一个新项目时，推荐这么写：

cmake_minimum_required(VERSION 3.15...4.4)
Tip

如果你确实需要在这里设置为一个较低的版本，你可以使用 cmake_policy 来有条件地提高策略级别或设置某项特定策略。

设置一个项目¶

接下来，每一个顶层 CMake 文件都应该包含下面这一行：

project(MyProject VERSION 1.0
                  DESCRIPTION "Very nice project"
                  LANGUAGES CXX)

现在我们看到了更多的语法。字符串使用引号括起来，空白字符无关紧要，而项目名称是第一个参数（位置参数）。这里所有的关键字参数都是可选的。版本号会设置一系列变量，例如 MyProject_VERSION 和 PROJECT_VERSION。支持的语言包括 C、CXX、Fortran、ASM、CUDA（CMake 3.8+）、CSharp（3.8+）、Swift（3.15+）、OBJC 与 OBJCXX（3.16+）、ISPC（3.18+）以及 HIP（3.21+），默认值为 C CXX。在 CMake 3.9 中，还新增了 DESCRIPTION 关键字来设置项目描述。关于 project 的文档可能会对你有所帮助。

Tip

你可以用 # 字符来添加注释。CMake 也有用于内联注释的语法，但极少用到。

项目名称并没有什么特别要注意的地方。到目前为止，我们还没有添加任何目标（target）。

生成一个可执行文件¶

尽管库要有趣得多，并且我们将会把大部分时间花在库上面，但现在让我们先从一个简单的可执行文件开始吧。

add_executable(one two.cpp three.h)

这里有几件事需要解释一下。one 既是生成的可执行文件的名称，也是创建的 CMake 目标（target）的名称（我保证，你很快就会听到更多关于目标的内容）。紧接着的是源文件列表，你想列多少个都可以。CMake 很聪明，它会根据扩展名只编译源文件。在绝大多数情况下，头文件都会被忽略；列出它们的唯一原因是为了让它们在 IDE 中显示出来。目标在许多 IDE 中会显示为文件夹。你可以在 buildsystem 中找到更多关于通用构建系统与目标的信息。

生成一个库¶

制作一个库是通过 add_library 命令完成的，同样非常简单：

add_library(one STATIC two.cpp three.h)

你可以选择库的类型，可以是 STATIC、SHARED 或 MODULE。如果你省略这一选择，CMake 将会根据 BUILD_SHARED_LIBS 的值在 STATIC 和 SHARED 之间进行选择。

正如你将在后续小节中看到的，你经常需要创建一个“虚构”的目标，也就是说一个不需要编译任何内容的目标，例如仅头文件库（header-only library）。这被称为 INTERFACE 库，它是另一种可选类型；唯一的区别是它后面不能跟文件名。

你也可以基于现有的库创建一个 ALIAS（别名）库，这只是给已有的目标起一个新的名字。这么做的一大好处是，你可以创建名称中带有 :: 的库（你将在后面看到）[3]。

目标时常伴随着你¶

现在我们已经指定了一个目标，那该如何添加关于它的信息呢？例如，它可能需要一个头文件包含目录：

target_include_directories(one PUBLIC include)

target_include_directories 会为目标添加一个包含目录。PUBLIC 对于可执行文件目标来说意义不大；但对于库来说，它让 CMake 知道，任何链接到这个目标的其他目标也必须包含该目录。其他选项还有 PRIVATE（只影响当前目标，不影响依赖它的目标），以及 INTERFACE（只对依赖它的目标生效）。

接下来我们可以将目标串联起来：

add_library(another STATIC another.cpp another.h)
target_link_libraries(another PUBLIC one)

target_link_libraries 可能是 CMake 中最有用也最令人困惑的命令。它接收一个目标（another），并在给定另一个目标时为其添加依赖关系。如果不存在名为 one 的目标，它就会在你的搜索路径中链接一个名为 one 的库（这也是该命令名称的由来）。或者你也可以传入库的完整路径，甚至是链接器标志（linker flag）。最后再补充一点容易混淆的地方：传统 CMake 允许你省略 PUBLIC 等关键字；但如果在某个目标上省略了关键字，而后续在依赖链中又混用了带关键字的写法，CMake 就会报错。

请专注于在所有地方都使用目标，并且在所有地方都写明关键字，这样就不会有问题。

目标可以拥有包含目录、链接库（或链接目标）、编译选项、编译定义、编译特性（见 C++ 标准章节）等等。正如你将在后面两个引入项目的章节中看到的，你通常都能获取到目标（并且总是可以自己创建目标）来代表你所使用的所有库。甚至像 OpenMP 这样并非真正意义上的库，也可以用目标来表示。这就是为什么现代 CMake 如此出色！

更进一步¶

看看你能否读懂下面这个文件。它构建了一个简单的 C++11 库以及一个使用该库的程序，没有任何外部依赖。我将在后面讨论更多关于 C++ 标准的选项，这里暂时使用 CMake 3.8 的方式。

cmake_minimum_required(VERSION 3.15...4.4)

project(Calculator LANGUAGES CXX)

add_library(calclib STATIC src/calclib.cpp include/calc/lib.hpp)
target_include_directories(calclib PUBLIC include)
target_compile_features(calclib PUBLIC cxx_std_11)

add_executable(calc apps/calc.cpp)
target_link_libraries(calc PRIVATE calclib)
