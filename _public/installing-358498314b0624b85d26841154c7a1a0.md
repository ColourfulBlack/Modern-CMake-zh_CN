# 安装 CMake

:::{tip}

你的 CMake 版本应该比你的编译器更新，也应该比你正在使用的所有库更新。新版本对所有人来说都更好用。

:::

如果你的系统中内置了 CMake，它并没有针对你的系统做任何特殊处理或定制。你可以轻松地在系统级别或用户级别安装一个新版本来替代它。如果你的用户抱怨 CMake 版本要求被设置得太高，请随时用这里的内容来指导他们——尤其是当他们需要 3.15+ 支持，甚至是需要 4.4+ 支持的时候……

## 官方安装包

你可以从 [KitWare 下载 CMake][download]。如果你使用的是 Windows，这很可能就是你获取 CMake 的方式。在 macOS 上通过这种方式获取也不错（官方提供了同时支持 Intel 和 Apple Silicon 的 Universal2 版本），但如果你使用 [Homebrew](https://brew.sh)，运行 `brew install cmake` 体验会好得多（你应该使用它；甚至苹果官方在推出 Apple Silicon 期间也为 Homebrew 提供了支持）。你也可以在大多数其他包管理器中获取它，比如 Windows 上的 [Chocolatey](https://chocolatey.org) 或 macOS 上的 [MacPorts](https://www.macports.org)。

在 Linux 上有几种选择。Kitware 提供了 [Debian/Ubuntu APT 软件源][apt]以及 [snap 软件包][snap]。官方也提供了通用的 Linux 二进制包，但你需要自行选择安装位置。如果你已经使用 `~/.local` 存放用户空间的软件包，下面这行单行命令[^1]即可为你安装好 CMake[^2]：

```bash
~ $ wget -qO- "https://cmake.org/files/v4.4/cmake-4.4.0-linux-x86_64.tar.gz" | tar --strip-components=1 -xz -C ~/.local
```

包名格式在 3.20 版本中发生了变化；更早的发行版包名类似于 `cmake-3.19.7-Linux-x86_64.tar.gz`。如果你只想要一个仅包含 CMake 的本地文件夹：

```bash
~ $ mkdir -p cmake-4.4 && wget -qO- "https://cmake.org/files/v4.4/cmake-4.4.0-linux-x86_64.tar.gz" | tar --strip-components=1 -xz -C cmake-4.4
~ $ export PATH=`pwd`/cmake-4.4/bin:$PATH
```

显然，你需要在每次打开新终端时将该路径追加到 `PATH`，或者将其添加到你的 `.bashrc` 或 [LMod][] 系统中。

此外，如果你想进行系统级安装，请安装到 `/usr/local`；这在 Docker 容器（例如 GitLab CI）中是一个极佳的选择。请不要在非容器化的系统上尝试这种做法。

```bash
docker $ wget -qO- "https://cmake.org/files/v4.4/cmake-4.4.0-linux-x86_64.tar.gz" | tar --strip-components=1 -xz -C /usr/local
```

如果你的系统上没有 `wget`，请用 `curl -s` 替换 `wget -qO-`。

你也可以在任何系统上从源码构建 CMake，这相当容易，不过直接使用二进制包会更快。

## Pip

[该软件包][pypi]同样作为官方包提供，由 KitWare 的 CMake 作者以及包括我本人在内的几位 PyPA 成员共同维护。它现在支持多种特殊架构（例如 Linux 上的 PowerPC 和 macOS 上的 Apple Silicon），同时也支持 Alpine 等基于 MUSL 的系统。如果你安装了 pip（Python 的软件包安装器），只需运行：

```bash
pip install cmake
```

只要存在适用于你系统的预编译二进制包，你几乎立刻就能安装完毕并投入使用。如果二进制包不存在，它会尝试从源码构建（该软件包使用 `scikit-build-core` 构建），但这要求系统中已经有一份可用的 CMake。因此，请仅在存在二进制包的情况下使用此方式——绝大多数时候都是有的。

这种方式还有一个好处，即能够遵循你当前的虚拟环境。不过，当把它写进 `pyproject.toml` 文件中时，它的优势才真正体现出来——它只会在构建你的软件包时被临时安装，构建完成后不会残留下来！简直太棒了。

当然，它也支持 pipx。因此你甚至可以直接使用 `pipx run cmake` 在一次性虚拟环境中运行 CMake，无需任何前置配置——而且这在 GitHub Actions 上开箱即用，因为 `pipx` 是那里原生支持的包管理器！

:::{tip}

就我个人而言，在 Linux 上我会把不同版本的 CMake 放进各自的文件夹中（比如 `/opt/cmake312` 或 `~/opt/cmake312`），然后再把它们添加到 [LMod][]。参见 [`envmodule_setup`][envmodule_setup]，它可以帮助你在 macOS 或 Linux 上配置 LMod 系统。这需要花点时间学习，但它是管理软件包和编译器版本的绝佳方式。

[envmodule_setup]: https://github.com/CLIUtils/envmodule_setup

:::

[^1]: 我想这显而易见，但你正在直接下载并运行代码，这会使你暴露在中间人攻击的风险之下。如果你处于关键环境中，应当先下载文件并校验校验和。（注意，仅仅分成两步执行并不会让你更安全，只有校验校验和才能保证安全。）

[^2]: 如果你的主目录中还没有 `.local` 目录，开始使用它也很简单。只需创建该文件夹，然后将 `export PATH="$HOME/.local/bin:$PATH"` 添加到主目录下的 `.bashrc`、`.bash_profile` 或 `.profile` 文件中。现在你就可以把自行构建的任何软件包安装到 `-DCMAKE_INSTALL_PREFIX=~/.local`，而不是 `/usr/local` 了！
