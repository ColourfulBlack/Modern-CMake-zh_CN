# 运行 CMake

在编写 CMake 之前，请先确保你已经清楚如何运行 CMake 来构建项目。这套方式适用于几乎所有的 CMake 项目——而如今几乎所有项目都是 CMake 项目。

## 构建项目

除非另有说明，否则你始终应该新建一个专门的构建目录并在其中执行构建。从技术上讲，你可以进行源码内构建（in-source build），但你必须格外小心以免覆盖原有文件或把构建产物误提交到 Git，所以别这么做就好。

以下是经典的 CMake 构建流程（TM）：

```bash
~/package $ mkdir build
~/package $ cd build
~/package/build $ cmake ..
~/package/build $ make
```

如果你愿意，可以把 `make` 这一行替换成 `cmake --build .`，它会自动调用 `make` 或你正在使用的任何底层构建工具。如果你使用的是较新版本的 CMake（除了检查与旧版 CMake 的兼容性之外，通常你都应该使用新版本），也可以直接这样做：

```bash
~/package $ cmake -S. -Bbuild
~/package $ cmake --build build
```

（其中 `-S` 指定包含 `CMakeLists.txt` 的源代码目录，`-B` 指定构建目录，若该目录不存在则会自动创建。）
以下**任意一条**命令都可以执行安装：

```bash
# 在构建目录中执行（任选其一）

~/package/build $ make install
~/package/build $ cmake --build . --target install
~/package/build $ cmake --install . # 仅限 CMake 3.15+

# 在源代码目录中执行（任选其一）

~/package $ make -C build install
~/package $ cmake --build build --target install
~/package $ cmake --install build # 仅限 CMake 3.15+
```

那么你应该选择哪一套方式呢？只要你**别忘记**输入构建目录作为参数，不进入构建目录的方式命令更简短，而且留在源代码目录中修改源码也更方便。你应该试着养成使用 `--build` 的习惯，因为这能让你摆脱只能用 `make` 构建的限制。需要注意的是，在构建目录下工作在历史上要普遍得多，并且一些工具和命令（包括 CTest <3.20）仍然要求在构建目录中运行。

补充说明一下，你既可以**在构建目录中**将 CMake 指向源代码目录，也可以在任意位置将 CMake 指向一个**已存在的**构建目录。

如果你使用 `cmake --build` 而不是直接调用底层构建系统，你可以用 `-v` 在构建时输出详细信息（CMake 3.14+），用 `-j N` 指定在 N 个核心上并行构建（CMake 3.12+），以及用 `--target`（任意版本的 CMake）或 `-t`（CMake 3.15+）来选择要构建的目标。如果直接调用底层构建工具，这些参数会因构建系统而异，例如 `VERBOSE=1 make` 和 `ninja -v`。你也可以使用对应的环境变量来代替命令行参数，例如 `CMAKE_BUILD_PARALLEL_LEVEL`（CMake 3.12+）和 `VERBOSE`（CMake 3.14+）。

## 指定编译器

指定编译器必须在空构建目录中首次运行 CMake 时进行。严格来说这并不是 CMake 自身的语法，但你可能还不太熟悉。如果要选用 Clang：

```bash
~/package/build $ CC=clang CXX=clang++ cmake ..
```

这条命令在 bash 中设置了环境变量 `CC` 和 `CXX`，CMake 会读取并遵循这些变量。如果你使用的是 Git Bash，则应当使用 `export` 将变量传递给子进程：

```bash
~/package/build $ export CC=clang CXX=clang++ cmake ..
```

这只会为当前这一行命令设置环境变量，但你也只需要在这一步设置一次；之后 CMake 会继续使用它从这些变量值推导出来的编译器路径。

## 指定生成器

你可以使用多种构建工具来进行构建；通常默认是 `make`。要查看当前系统上 CMake 所支持的全部构建工具，请运行：

```bash
~/package/build $ cmake --help
```

你可以用 `-G"My Tool"`（仅当工具名称中包含空格时才需要加引号）来指定构建工具。和指定编译器一样，你应该在该目录中第一次调用 CMake 时就指定好构建工具。你完全可以同时保留多个构建目录，比如 `build/` 和 `buildXcode`。
你可以通过设置环境变量 `CMAKE_GENERATOR` 来控制默认生成器（CMake 3.15+）。
需要注意的是，Makefile 只有在你显式传入线程数（例如 `make -j2`）时才会并行构建，而 Ninja 则默认就会自动并行运行。在较新版本的 CMake 中，你可以直接将 `-j2` 之类的并行选项传给 `cmake --build .` 命令。

## 设置选项

在 CMake 中，你可以使用 `-D` 设置选项。你可以使用 `-L` 查看所有选项列表，或者用 `-LH` 查看附带人类可读帮助说明的选项列表。如果你没有传入源代码目录或构建目录，查看列表时将不会重新运行 CMake（即使用 `cmake -L` 而不是 `cmake -L .`）。

## 详细构建与部分构建

虽然并非所有构建工具都支持，但你可以通过以下方式获得详细的构建输出（任选其一）：

```bash
~/package $ cmake --build build --verbose # 仅限 CMake 3.14+
~/package/build $ VERBOSE=1 make
```

实际上你写成 `make VERBOSE=1`，`make` 也能正确执行，不过这是 `make` 自身的特性，而非通用的命令行写法。

你也可以通过指定某个目标（例如你在 CMake 中定义的库或可执行文件的名称）来仅构建项目的一部分，此时 `make` 将只构建该目标。

## 选项

CMake 支持缓存选项。CMake 中的变量可以被标记为“cached”（缓存变量），这意味着当遇到该变量时，它会被写入缓存（即构建目录中名为 `CMakeCache.txt` 的文件）。你可以在命令行上通过 `-D` 预先设定（或修改）缓存选项的值。当 CMake 查找缓存变量时，它会直接使用已有的值而不会覆盖它。

### 标准选项

以下是大多数软件包通用的常见 CMake 选项：

- `-DCMAKE_BUILD_TYPE=` 从 `Release`、`RelWithDebInfo`、`Debug`（有时还有其他类型）中选择构建类型。
- `-DCMAKE_INSTALL_PREFIX=` 安装目标位置。UNIX 系统上系统级安装的默认位置通常是 `/usr/local`，用户级目录通常是 `~/.local`，或者你也可以指定任意文件夹。
- `-DBUILD_SHARED_LIBS=` 你可以将其设置为 `ON` 或 `OFF` 来控制共享库的默认构建行为（不过库作者也可以显式指定构建静态库或共享库，而不使用该默认值）。
- `-DBUILD_TESTING=` 这是启用测试的常用选项名称，不过并非所有软件包都使用它（有时这样做确有其合理原因）。

## 调试你的 CMake 文件

前面我们已经提到了构建阶段的详细输出，其实你同样可以查看 CMake 配置阶段的详细输出。`--trace` 选项会打印出所运行的每一行 CMake 代码。由于它的输出过于冗长，CMake 3.7 新增了 `--trace-source="filename"` 选项，运行时只会打印出你所关心的那个特定文件中实际执行的每一行。只要指定你想调试的文件名（调试 `CMakeLists.txt` 时通常会连带指定父目录名，因为所有目录下的 `CMakeLists.txt` 同名），你就能只看到该文件中被执行的语句。非常实用！
