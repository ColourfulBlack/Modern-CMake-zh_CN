# GoogleTest

[GoogleTest] 和 GoogleMock 是非常经典的选择；不过就我个人而言，我会推荐你改用 Catch2，因为 GoogleTest 高度遵循 Google 的开发理念：它会非常迅速地放弃对旧编译器的支持，假定用户总是希望直接使用最新主干代码（live at HEAD）等等。添加 GoogleMock 也常常令人头疼——而且你必须引入 GoogleMock 才能使用匹配器（matcher），而这在 Catch2 中是默认自带的特性（不过 doctest 没有这个特性）。

## FetchContent 方式

FetchContent 模块自身的文档就是以 GoogleTest 作为示例的，这也是获取它最简单的方式：

```cmake
include(FetchContent)

FetchContent_Declare(
  googletest
  GIT_REPOSITORY https://github.com/google/googletest.git
  GIT_TAG        v1.17.0
)

FetchContent_MakeAvailable(googletest)
```

这会提供带命名空间的目标 `GTest::gtest`、`GTest::gtest_main`、`GTest::gmock` 和 `GTest::gmock_main`；它们与针对已安装副本调用 `find_package(GTest)` 所提供的目标完全一致（现代版本的 GoogleTest 支持标准的 CMake 安装流程，因此直接使用打包安装好的副本也完全没问题）。

## 子模块（Submodule）方式

使用这种方式时，只需将 GoogleTest 检出（checkout）为一个子模块：[^1]

```bash
git submodule add --branch=v1.17.x ../../google/googletest.git extern/googletest
```

然后，在你的主 `CMakeLists.txt` 中：

```cmake
option(PACKAGE_TESTS "Build the tests" ON)
if(PACKAGE_TESTS)
    enable_testing()
    include(GoogleTest)
    add_subdirectory(tests)
endif()
```

我推荐你使用类似 `PROJECT_NAME STREQUAL CMAKE_PROJECT_NAME` 的条件来设置 `PACKAGE_TESTS` 选项的默认值，因为只有当该项目作为当前主项目时才应该默认构建测试。
正如之前提到的，你必须在主 `CMakeLists.txt` 中调用 `enable_testing`。

现在，在你的 `tests` 目录中：

```cmake
add_subdirectory("${PROJECT_SOURCE_DIR}/extern/googletest" "extern/googletest")
```

如果你是在主 `CMakeLists.txt` 中调用它的，那么可以直接使用普通的 `add_subdirectory`；这里因为我们是从子目录中调用它的，所以需要额外指定第二个路径参数来修正构建路径。

下面这段代码是可选的，但可以让你的 `CACHE` 保持更整洁：

```cmake
mark_as_advanced(
    BUILD_GMOCK BUILD_GTEST BUILD_SHARED_LIBS
    gmock_build_tests gtest_build_samples gtest_build_tests
    gtest_disable_pthreads gtest_force_shared_crt gtest_hide_internal_symbols
)
```

如果你希望在支持文件夹分组的 IDE 中保持界面整洁，我还会加上下面几行：

```cmake
set_target_properties(gtest PROPERTIES FOLDER extern)
set_target_properties(gtest_main PROPERTIES FOLDER extern)
set_target_properties(gmock PROPERTIES FOLDER extern)
set_target_properties(gmock_main PROPERTIES FOLDER extern)
```

## 添加测试

无论你通过哪种方式引入了 GoogleTest，在添加测试时，我都推荐使用下面的宏：

```cmake
macro(package_add_test TESTNAME)
    # 创建一个用于存放测试的可执行文件
    add_executable(${TESTNAME} ${ARGN})
    # 将 GoogleTest 基础库、Mock 库以及默认的 main 函数链接到测试可执行文件。
    # 如果你要自己编写 main 函数，请移除 GTest::gtest_main。
    target_link_libraries(${TESTNAME} GTest::gtest GTest::gmock GTest::gtest_main)
    # gtest_discover_tests 取代了 gtest_add_tests，
    # 更多可传入的选项请参见 https://cmake.org/cmake/help/latest/module/GoogleTest.html
    gtest_discover_tests(${TESTNAME}
        # 将工作目录设置为项目根目录，以便通过相对于项目根目录的路径查找测试数据
        WORKING_DIRECTORY ${PROJECT_SOURCE_DIR}
        PROPERTIES VS_DEBUGGER_WORKING_DIRECTORY "${PROJECT_SOURCE_DIR}"
    )
    set_target_properties(${TESTNAME} PROPERTIES FOLDER tests)
endmacro()

package_add_test(test1 test1.cpp)
```

这能让你快速而简单地添加测试。你可以根据自己的需求随意调整。如果你之前没见过 `ARGN`，它代表“已列出的参数之后的所有其余参数”。
你可以修改这个宏来满足自己的需求。例如，如果你正在测试多个库，并且需要针对不同的测试链接不同的库，可以这样写：

```cmake
macro(package_add_test_with_libraries TESTNAME FILES LIBRARIES TEST_WORKING_DIRECTORY)
    add_executable(${TESTNAME} ${FILES})
    target_link_libraries(${TESTNAME} GTest::gtest GTest::gmock GTest::gtest_main ${LIBRARIES})
    gtest_discover_tests(${TESTNAME}
        WORKING_DIRECTORY ${TEST_WORKING_DIRECTORY}
        PROPERTIES VS_DEBUGGER_WORKING_DIRECTORY "${TEST_WORKING_DIRECTORY}"
    )
    set_target_properties(${TESTNAME} PROPERTIES FOLDER tests)
endmacro()

package_add_test_with_libraries(test1 test1.cpp lib_to_test "${PROJECT_SOURCE_DIR}/european-test-data/")
```

[^1]: 这里我使用了指向 googletest 的相对路径，因此假定了你正在 GitHub 仓库中进行开发。

[googletest]: https://github.com/google/googletest
