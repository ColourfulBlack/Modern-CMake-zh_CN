# CUDA

CUDA 支持有两种方式。CMake 3.8（Windows 为 3.9）中引入的新方法，应当优先于陈旧而繁琐的传统方法 —— 这里提到旧方法，只是因为某些老旧的包中仍很有可能在使用它。与较早支持的语言不同，CUDA 支持一直在快速演进，而且构建 CUDA 本身非常困难，因此建议*要求使用尽可能新的版本*的 CMake！CMake 3.17 和 3.18 包含大量直接针对 CUDA 的改进。

对于 CUDA 和现代 CMake 来说，一个很好的参考资料是 CMake 开发者 Robert Maynard 在 GTC 2017 上的[演讲 PPT](https://web.archive.org/web/20240222053415/https://on-demand.gputechconf.com/gtc/2017/presentation/S7438-robert-maynard-build-systems-combining-cuda-and-machine-learning.pdf)。

## 启用 CUDA 语言

启用 CUDA 支持有两种方法。若 CUDA 支持不是可选的：

```cmake
project(MY_PROJECT LANGUAGES CUDA CXX)
```

这里通常还需要将 `CXX` 一并列出。若 CUDA 支持是可选的，则需要在条件语句中启用它：

```cmake
enable_language(CUDA)
```

要检查 CUDA 是否可用，可使用 `check_language`：

```cmake
include(CheckLanguage)
check_language(CUDA)
```

可以通过检查 `CMAKE_CUDA_COMPILER`（CMake 3.11 之前不存在）来查看 CUDA 是否存在。

可以检查诸如 `CMAKE_CUDA_COMPILER_ID` 之类的变量（对于 nvcc，其值为 `"NVIDIA"`，CMake 3.18 起新增了 Clang 支持）。可以用 `CMAKE_CUDA_COMPILER_VERSION` 检查 CUDA 版本。

## CUDA 的变量

CMake 中许多名称带有 `CXX` 的变量都有对应的 `CUDA` 版本。例如，要设置 CUDA 所需的 C++ 标准：

```cmake
if(NOT DEFINED CMAKE_CUDA_STANDARD)
    set(CMAKE_CUDA_STANDARD 11)
    set(CMAKE_CUDA_STANDARD_REQUIRED ON)
endif()
```

若要指定 CUDA 的标准级别，CMake 3.17 中新增了一组编译器特性，例如 `cuda_std_11`。它们具有与你早已熟悉的 `cxx` 版本特性相同的优势。

### 添加库/可执行文件

这部分很简单；只要 CUDA 文件使用 `.cu` 后缀，就可以*像平常一样*直接添加库。

也可以使用分离编译（separable compilation）：

```cmake
set_target_properties(mylib PROPERTIES
                            CUDA_SEPARABLE_COMPILATION ON)
```

也可以直接使用 `CUDA_PTX_COMPILATION` 属性生成 PTX（Parallel Thread eXecution）文件。

### 目标架构

构建 CUDA 代码时，通常应当指定目标架构。若不指定，则会针对受支持的最低架构编译 PTX；它提供基本指令并在运行时编译，这可能会使加载速度慢得多。

所有显卡都有一个架构级别，例如 `"7.2"`。在处理架构时有两个层面的选择：首先是代码级别，它会向正在编译的代码报告一个版本号（例如 `"5.0"`），代码将利用最高到 5.0 但不超过 5.0 的所有特性（假设代码和标准库编写良好）；其次是目标架构，它必须大于或等于代码架构，且主版本号需与目标显卡一致、版本号小于或等于目标显卡，因此对于架构为 7.2 的显卡，7.0 是常见的选择。最后，还可以生成 PTX；PTX 可以在未来的所有显卡上运行，但会在运行时进行即时（JIT）编译。

在 CMake 3.18 中，设置目标架构变得非常容易。若项目的版本范围包含 CMake 3.18 或更高版本，可以使用 `CMAKE_CUDA_ARCHITECTURES` 变量以及目标上的 `CUDA_ARCHITECTURES` 属性。可以列出具体数值（不带 `.`），比如用 `50` 表示架构 5.0。这将同时针对真实架构（SASS）和虚拟架构（PTX）生成代码。传入 `'50-real'` 将仅针对 SASS 生成代码，而传入 `'50-virtual'` 则仅针对 PTX 生成代码。若设置为 `OFF`，则不会传递任何架构信息。

在 CMake 3.23 中，架构取值得到了扩展，支持对用户更友好的 `'all'` 和 `'all-major'`；CMake 3.24 又新增了 `'native'`。

### 使用目标

使用目标应当与 `CXX` 类似，但存在一个问题。若引入的目标包含编译器选项（标志），大多数情况下这些选项并没有用正确的条件生成表达式加以保护（正确封装了 CUDA 包装选项的可能性更是微乎其微）。正确的编译器选项设置应当如下所示：

```cmake
set(opt "$<$<BUILD_INTERFACE:$<COMPILE_LANGUAGE:CXX>>:-fopenmp>$<$<BUILD_INTERFACE:$<COMPILE_LANGUAGE:CUDA>>:-Xcompiler=-fopenmp>")
```

然而，如果配合几乎任何 `find_package` 使用现代 CMake 的目标和继承方式，一切都会出错。这是我吃了不少苦头才总结出来的经验。

目前有一个相当合理的解决方案，*前提是知道未起别名的原始目标名称*。下面这个函数在使用 CUDA 编译器时，会通过包装编译标志来修复仅面向 C++ 的目标：

```cmake
function(CUDA_CONVERT_FLAGS EXISTING_TARGET)
    get_property(old_flags TARGET ${EXISTING_TARGET} PROPERTY INTERFACE_COMPILE_OPTIONS)
    if(NOT "${old_flags}" STREQUAL "")
        string(REPLACE ";" "," CUDA_flags "${old_flags}")
        set_property(TARGET ${EXISTING_TARGET} PROPERTY INTERFACE_COMPILE_OPTIONS
            "$<$<BUILD_INTERFACE:$<COMPILE_LANGUAGE:CXX>>:${old_flags}>$<$<BUILD_INTERFACE:$<COMPILE_LANGUAGE:CUDA>>:-Xcompiler=${CUDA_flags}>"
            )
    endif()
endfunction()
```

### 常用变量

即使不启用 CUDA 语言，也可以使用 [`FindCUDAToolkit`](https://cmake.org/cmake/help/latest/module/FindCUDAToolkit.html) 来查找各种实用的目标和变量。

```cmake
cmake_minimum_required(VERSION 3.17)
project(example LANGUAGES CXX)

find_package(CUDAToolkit REQUIRED)
add_executable(uses_cublas source.cpp)
target_link_libraries(uses_cublas PRIVATE CUDA::cublas)
```

使用 `find_package(CUDAToolkit)` 提供的变量：

- `CUDAToolkit_BIN_DIR`：存放 `nvcc` 可执行文件的目录
- `CUDAToolkit_INCLUDE_DIRS`：包含内置 Thrust 等工具头文件的目录列表
- `CUDAToolkit_LIBRARY_DIR`：存放 CUDA 运行时库的目录

启用 `CUDA` 语言提供的变量：

- `CMAKE_CUDA_COMPILER`：NVCC 编译器的路径
- `CMAKE_CUDA_TOOLKIT_INCLUDE_DIRECTORIES`：内置 Thrust 等工具头文件所在的位置

:::{warning}

传统的 FindCUDA 模块已被弃用多年，并最终在 CMake 3.27 中移除（策略 [CMP0146](https://cmake.org/cmake/help/latest/policy/CMP0146.html)）；在任何现代 CMake 版本中，调用 `find_package(CUDA)` 都会直接报错。在 CMake 3.18 之前，以下功能确实仍需要依赖 FindCUDA：

- CUDA 版本检查/选择版本
- 架构检测（注：3.12 部分修复了该问题）
- 从非 `.cu` 文件链接 CUDA 库

:::

## 传统的 FindCUDA [警告：已在 CMake 3.27 中移除]（仅供参考）

下面的做法仅在低于 3.27 版本的 CMake 上有效，因为在此之后该模块已不复存在。若受困于必须支持如此老旧的 CMake，建议至少在项目的 cmake 文件夹中包含来自 CMake 3.9 版本的 FindCUDA（参见 CLIUtils GitHub 组织中的 [Git 仓库](https://github.com/CLIUtils/cuda_support)）。你会需要其中新增的两个特性：`CUDA_LINK_LIBRARIES_KEYWORD` 和 `cuda_select_nvcc_arch_flags`，以及较新的架构和 CUDA 版本支持。

要使用旧版 CUDA 支持方式，需调用 `find_package`：

```cmake
find_package(CUDA 7.0 REQUIRED)
message(STATUS "Found CUDA ${CUDA_VERSION_STRING} at ${CUDA_TOOLKIT_ROOT_DIR}")
```

可以用 `CUDA_NVCC_FLAGS`（通过 `list(APPEND)` 追加）控制 CUDA 编译标志，通过 `CUDA_SEPARABLE_COMPILATION` 控制分离编译。若想确保 CUDA 与现代目标机制良好配合并为目标添加关键字（CMake 3.9+），还需要设置：

```cmake
set(CUDA_LINK_LIBRARIES_KEYWORD PUBLIC)
```

若想允许用户检测当前硬件对应的架构标志，可以使用以下方式：

```cmake
cuda_select_nvcc_arch_flags(ARCH_FLAGS) # 可传入可选参数以指定要添加的架构
```
