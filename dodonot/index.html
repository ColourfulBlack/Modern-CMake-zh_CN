CMake 行为准则（Do’s and Don’ts）

接下来的两个列表很大程度上基于优秀的 Gist Effective Modern CMake。原列表要长得多也详细得多，非常欢迎你也去阅读一下。

CMake 反模式（应避免的行为）¶

  • 不要使用全局函数：这包括 link_directories、include_directories 以及类似的函数。

  • 不要添加非必要的 PUBLIC 依赖要求：你应该避免把非必需的选项（例如 -Wall）强加给用户。请改用 PRIVATE。

  • 不要使用 GLOB 收集文件：如果不重新运行 CMake，Make 或其他构建工具将无法感知你是否新增了文件。需要注意的是，CMake 3.12 新增了 CONFIGURE_DEPENDS 标志，如果你确实需要使用 GLOB，它会让体验好得多。

  • 不要直接链接到已构建的文件：只要有可用的目标（target），请始终链接到目标。

  • 链接时切勿省略 PUBLIC/PRIVATE 关键字：一旦省略，会导致后续所有的链接都无法再使用关键字形式。

CMake 推荐模式（应遵守的规范）¶

  • 把 CMake 视作代码：它本身就是代码，应该像其他所有代码一样整洁、易读。

  • 建立以目标为核心的思维：你的目标应当代表逻辑概念。对于任何应该组合在一起传递的配置或依赖，请创建一个（IMPORTED）INTERFACE 目标并链接到该目标。

  • 导出你的接口：你的项目应当既能直接从构建目录运行或使用，也能在安装后使用。

  • 编写 Config.cmake 文件：这是库作者为了支持下游用户所应当做的。

  • 创建 ALIAS 目标以保持用法一致：通过 add_subdirectory 和 find_package 引入时，应当提供相同的目标名称和命名空间。

  • 将通用功能封装到文档清晰的函数或宏中：通常函数是更好的选择。

  • 使用小写的函数名：CMake 的函数和宏在调用时不区分大小写，请始终使用小写；大写留给变量名。

  • 使用 cmake_policy 和/或指定版本范围：策略（policy）的变更皆有其原因。只有在万不得已时，才针对个别策略单独设置为 OLD。

在 2026 年选择最低版本¶

在本地开发时你应该运行哪个最低版本的 CMake？对于使用你代码的用户，你又应该支持哪个最低版本？既然你正在阅读本书，你应该能够获取到最近几个版本的 CMake 发行版；请直接安装新版本，这会让你的开发工作轻松得多。至于项目所支持的最低版本，有两种选择方式：一种是基于新增的功能特性（这是开发者关心的），另一种是基于常见的系统预装 CMake 版本（这是用户关心的）。

切勿选择比你所支持的最老编译器还要古老的 CMake 最低版本。CMake 的版本始终应当至少与最初支持该最老编译器的 CMake 版本一样新。

如何选择最低版本——操作系统支持：¶

  • 3.19：首个支持 Apple Silicon 的版本。

  • 3.22：Ubuntu 22.04、Amazon Linux 2023。

  • 3.25：Debian 12（以及 Debian 11 backports）。

  • 3.26：Rocky Linux 9、AlmaLinux 9（当前小版本更新中已升至 3.31）。

  • 3.28：Ubuntu 24.04。

  • 3.30：Rocky Linux 10、AlmaLinux 10、CentOS Stream 10（当前更新中已升至 3.31）。

  • 3.31：Debian 13（以及 Debian 12 backports）。

  • latest（最新版）：pip / conda-forge / Homebrew / Chocolatey 等。

如何选择最低版本——功能特性：¶

  • 3.11：IMPORTED INTERFACE 设置、构建提速、FetchContent、IDE 中的 COMPILE_LANGUAGE 支持

  • 3.12：C++20、cmake --build build -j N、SHELL:、FindPython

  • 3.14/3.15：命令行接口（CLI）增强、FindPython 更新

  • 3.16：Unity 构建（Unity builds）/ 预编译头（precompiled headers）、CUDA 元特性（meta features）

  • 3.17/3.18：更多 CUDA 支持、元编程（metaprogramming）、FindPython 更新

  • 3.19：预设（Presets）

  • 3.20：C++23、cmake_path

  • 3.24：包查找器（Package finder）集成机制

  • 3.25：用于作用域控制的 block()（Blocks for scoping）

  • 3.28：C++20 模块（modules）

  • 3.29：测试前自动构建目标（Build before test target）

  • 3.30：完整的 C++26 支持
